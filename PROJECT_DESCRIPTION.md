# Retail Management System (RMS) – Комплексная система управления розничной торговлей в РФ

## 1. Введение

Проект представляет собой полнофункциональную систему для автоматизации розничной торговли в Российской Федерации, учитывающую все актуальные законодательные требования: 54-ФЗ, маркировка «Честный знак», ЕГАИС, ЭДО, а также поддержку услуг, бронирования, доставки и гибкой системы уведомлений.

Система предназначена для использования в магазинах, сетях, пунктах выдачи, интернет-магазинах и сервисных центрах, обеспечивая единое пространство для учёта товаров, управления продажами, взаимодействия с клиентами и отчётности.

## 2. Технологический стек

| Компонент | Технология |
|-----------|------------|
| **Backend** | Go 1.22+, Gin/Echo, GORM, pgx, golang-migrate, JWT, Redis, Asynq/RabbitMQ |
| **Frontend** | React 18, TypeScript, Tailwind CSS, React Router v6, React Query, Zustand/Redux Toolkit, Axios |
| **База данных** | PostgreSQL 14+ (с индексами, партиционированием, материализованными представлениями) |
| **Инфраструктура** | Docker, docker-compose, Kubernetes (опционально), CI/CD (GitHub Actions), мониторинг (Prometheus/Grafana), логирование (ELK/Loki) |
| **Документация API** | OpenAPI 3.0 (Swagger) |

## 3. Структура базы данных

База данных содержит следующие логические модули (полная схема описана в отдельных SQL-скриптах):

- **Core**: организации, контрагенты, сотрудники, склады, категории, бренды, товары (включая услуги), упаковки, цены, партии, коды маркировки.
- **Документооборот**: заказы поставщикам, поступления, перемещения, инвентаризации, заказы покупателей, отгрузки, кассовые чеки.
- **Налоговый учёт**: книги покупок/продаж, регистры налогового учёта, декларационные регистры.
- **Интеграции**: настройки ОФД, ЕГАИС, маркетплейсов, универсальный лог интеграций.
- **Детали ОФД и ЕГАИС**: расшифровка чеков по ФФД, маршрутные листы, акты списания, журналы.
- **Пользователи и безопасность**: пользователи, роли, разрешения, сессии, аудит, приглашения.
- **Услуги и бронирование**: ресурсы, расписания, бронирования, история статусов.
- **Доставка**: заказы на доставку, зоны, курьеры, назначения, статусы.
- **Статусы товаров**: справочник статусов с датами действия.
- **Уведомления**: типы, каналы, шаблоны, очередь, история, предпочтения пользователей.

## 4. Архитектура приложения

### Backend (Go)

- **Слой маршрутов и контроллеров**: REST API эндпоинты, валидация входных данных, преобразование в DTO.
- **Слой сервисов**: бизнес-логика (управление товарами, заказами, кассой, маркировкой, доставкой, уведомлениями).
- **Слой репозиториев**: работа с БД через GORM, выполнение сложных запросов, использование транзакций.
- **Middleware**: аутентификация (JWT), авторизация (RBAC), логирование запросов, обработка паники, CORS.
- **Фоновые задачи**: воркеры для отправки уведомлений (email, SMS, push, Telegram), обработки очередей интеграций (ОФД, ГИС МТ, ЕГАИС, маркетплейсы), периодические задачи (cron): проверка истечения статусов, напоминания о бронированиях, синхронизация с внешними системами.
- **Кэширование**: Redis для хранения сессий, временных данных, частых запросов (например, справочники).
- **Логирование**: структурированное логирование (JSON) с отправкой в ELK/Loki.

### Frontend (React)

- **Компонентная архитектура**: папки по функциональным модулям (`auth`, `products`, `orders`, `cash`, `services`, `delivery`, `reports`, `admin`).
- **Маршрутизация**: защищённые маршруты в зависимости от роли пользователя.
- **Управление состоянием**: React Query для серверных данных (кэширование, ревалидация), Zustand для глобального состояния UI (тема, уведомления, модальные окна).
- **UI-библиотека**: Tailwind CSS + Shadcn/ui или Headless UI для готовых компонентов.
- **Формы и валидация**: React Hook Form + Zod.
- **Работа с API**: Axios с перехватчиками для добавления токена, обработки ошибок, обновления токена.
- **Дашборды**: Recharts или Chart.js для визуализации аналитики.

### Инфраструктура

- **Локальная разработка**: Docker Compose с контейнерами: backend, postgres, redis, frontend (в режиме разработки).
- **Production**: контейнеризация, оркестрация (Kubernetes/Docker Swarm), reverse proxy (nginx/traefik), SSL.
- **CI/CD**: автоматические сборка, тестирование, деплой при пуше в основную ветку.
- **Мониторинг и алертинг**: Prometheus для сбора метрик, Grafana для дашбордов, Alertmanager для оповещений.
- **Резервное копирование**: автоматические бэкапы PostgreSQL с возможностью восстановления.

## 5. Функциональные модули

### 5.1. Управление пользователями и организациями

- Регистрация и аутентификация (JWT).
- Управление организациями и их реквизитами.
- Роли и разрешения (RBAC): SUPER_ADMIN, ADMIN, MANAGER, CASHIER, ACCOUNTANT, WAREHOUSE_MANAGER, VIEWER.
- Приглашения сотрудников по email.
- Личный кабинет с настройками профиля.
- Журнал аудита действий пользователей.

### 5.2. Справочники и товары

- Категории, бренды, единицы измерения.
- Товары (SKU, GTIN, цены, НДС, маркировка, срок годности, серийный учёт).
- Услуги (длительность, необходимость бронирования, ресурсы).
- Упаковки товаров для маркировки (потребительская, групповая, транспортная).
- Цены и типы цен (розничная, оптовая, закупочная).
- Связь с партиями, сроками годности.
- Статусы товаров (активен, новинка, распродажа, снят с продажи и т.д.) с датами действия.

### 5.3. Складской учёт и движение товаров

- Склады, зоны хранения.
- Поступление товаров от поставщиков (с поддержкой ЭДО и кодов маркировки).
- Перемещение между складами.
- Инвентаризация (с фиксацией расхождений).
- Остатки на складах (в разрезе партий, упаковок).
- Резервирование остатков под заказы покупателей.

### 5.4. Кассовые операции и фискализация (54-ФЗ)

- Кассовые чеки (продажа, возврат, коррекция).
- Поддержка ФФД 1.2 с детализацией позиций (признаки предмета, способа расчета, ставки НДС).
- Интеграция с ОФД через очередь отправки, обработка ответов, обновление фискальных признаков.
- Связь чеков с кодами маркировки.
- Кассовые смены, X/Z-отчёты.

### 5.5. Маркировка «Честный знак»

- Регистрация кодов маркировки (DataMatrix) в системе.
- Проверка подлинности и статуса при продаже (онлайн через ГИС МТ или локальный модуль).
- Автоматическая передача данных о выбытии кодов при продаже.
- Очередь запросов к ГИС МТ с логированием.
- Поддержка групповой упаковки (КИГУ, КИТУ).

### 5.6. Заказы и продажи

- Заказы покупателей (розничные, оптовые, интернет-заказы).
- Резервирование товаров на складе.
- Отгрузка заказов, формирование УПД (интеграция с ЭДО).
- Кредитные лимиты для контрагентов.
- История статусов заказов.

### 5.7. Услуги и бронирование

- Управление ресурсами (сотрудники, помещения, оборудование).
- Расписание работы ресурсов и исключения (праздники, отгулы).
- Бронирование услуг с проверкой доступности ресурсов.
- Статусы бронирований (ожидает, подтверждено, выполняется, выполнено, отменено, неявка).
- Автоматические напоминания о предстоящих бронированиях.
- Привязка бронирований к чекам и заказам.

### 5.8. Доставка

- Заказы на доставку с указанием адреса, даты, времени.
- Типы доставки (курьер, самовывоз, почта, СДЭК и др.).
- Зоны доставки с расчётом стоимости.
- Курьеры (сотрудники) с графиком работы и зонами закрепления.
- Назначение курьера на доставку, трек-номер, отслеживание статусов.
- История статусов доставки.
- Интеграция с внешними службами доставки (опционально).

### 5.9. ЭДО, ЕГАИС и маркетплейсы

- **ЭДО**: обмен УПД с контрагентами, подписание электронной подписью, работа с операторами ЭДО.
- **ЕГАИС**: учёт алкогольной продукции, маршрутные листы, акты списания, декларации, обмен XML-сообщениями, журнал ЕГАИС.
- **Маркетплейсы**: синхронизация заказов, остатков, цен с Ozon, Wildberries, Яндекс.Маркет и др.; логи синхронизации.
- Централизованный лог всех интеграций.

### 5.10. Налоговый учёт и отчётность

- Ведение книг покупок и продаж (НДС).
- Регистры налогового учёта для налога на прибыль и УСН.
- Декларационные регистры для автоматического заполнения налоговых деклараций.
- Экспорт отчётов в Excel и PDF.
- Формирование алкогольных деклараций (ФС РАР).

### 5.11. Уведомления

- Типы уведомлений (заказ, доставка, бронирование, платежи, системные).
- Каналы: email, SMS, push, Telegram, веб-интерфейс.
- Шаблоны уведомлений с поддержкой переменных.
- Очередь уведомлений с приоритетами и повторными попытками.
- История отправленных уведомлений.
- Настройка предпочтений для каждого пользователя (вкл/выкл конкретные уведомления и каналы).

## 6. Бизнес-процессы (сквозные сценарии)

1. **Регистрация и настройка организации**  
   - Администратор создаёт организацию, добавляет сотрудников, назначает роли.  
   - Настраивает ККТ, ОФД, ЕГАИС, маркетплейсы, зоны доставки.

2. **Учёт товаров**  
   - Сотрудник склада создаёт товары с ценами, категориями, при необходимости – кодами маркировки.  
   - Для услуг указывает длительность и связь с ресурсами.

3. **Поступление товаров**  
   - Менеджер оформляет поступление на основании УПД (приходит по ЭДО).  
   - Сканирует коды маркировки или загружает из файла.  
   - При проведении документа обновляются остатки и пул маркировки.

4. **Продажа в розницу**  
   - Кассир на кассе выбирает товары, сканирует коды маркировки (для маркированных товаров).  
   - Пробивается чек, отправляется в ОФД, фискализируется.  
   - Данные о продаже маркировки передаются в ГИС МТ (асинхронно).  
   - Если чек содержит услугу, автоматически создаётся бронирование (если требуется предзапись).

5. **Заказ через интернет-магазин/менеджера**  
   - Клиент или менеджер оформляет заказ, система резервирует товары.  
   - Опционально создаётся доставка с выбором типа и курьера.  
   - После оплаты формируется чек, заказ переходит в статус «отгружен».

6. **Бронирование услуги**  
   - Клиент выбирает услугу, дату и время.  
   - Система проверяет доступность ресурсов (сотрудники, кабинеты).  
   - Создаётся бронирование, отправляется подтверждение.  
   - За день до бронирования система отправляет напоминание.

7. **Доставка заказа**  
   - После создания заказа менеджер назначает курьера и зону.  
   - Курьер забирает заказ, система отслеживает статусы (забран, в пути, доставлен).  
   - Клиент получает уведомления о каждом изменении статуса.

8. **Интеграции с внешними системами**  
   - **ЭДО**: автоматический обмен УПД с контрагентами через оператора.  
   - **ЕГАИС**: формирование маршрутных листов, отправка актов списания, деклараций.  
   - **Маркетплейсы**: периодическая синхронизация остатков и заказов (по расписанию или по событию).

9. **Налоговая отчётность**  
   - По окончании квартала автоматически формируются книги покупок/продаж, декларации по НДС и налогу на прибыль.  
   - Алкогольные декларации формируются и отправляются в ФС РАР.

10. **Уведомления**  
    - Система автоматически отправляет клиентам и сотрудникам уведомления по email/SMS/push:  
      - о создании заказа, изменении статуса доставки, подтверждении бронирования, напоминаниях.  
      - о низком остатке товаров или скором истечении срока годности кодов маркировки.

11. **Аудит и безопасность**  
    - Все действия пользователей записываются в `audit_log` с указанием IP, времени, данных до/после.  
    - Администратор может просматривать журнал для выявления нарушений.

## 7. Безопасность

- **Аутентификация**: JWT-токены с ограниченным временем жизни, обновление через refresh-токены.
- **Авторизация**: роли и разрешения (RBAC) на уровне эндпоинтов и данных (доступ к определённым организациям).
- **Хранение паролей**: bcrypt с солью.
- **Защита API**: CORS, лимиты запросов, валидация входящих данных.
- **Аудит**: логирование всех критичных действий (изменение документов, кассовые операции, входы).
- **SSL/TLS**: все соединения шифруются.

## 8. Интеграции

| Интеграция | Описание |
|------------|----------|
| **ОФД** | Отправка чеков, получение фискального признака, регистрация ККТ |
| **ГИС МТ («Честный знак»)** | Регистрация кодов, проверка, вывод из оборота |
| **ЕГАИС** | Учёт алкоголя, маршрутные листы, декларации, акты |
| **ЭДО** | Обмен УПД, подписание электронной подписью |
| **Маркетплейсы** | Синхронизация заказов, остатков, цен (Ozon, Wildberries, Яндекс.Маркет) |
| **Службы доставки** | API для расчёта стоимости, создания заказов, отслеживания (опционально) |
| **Почтовые/SMS-сервисы** | Отправка уведомлений (SendPulse, Unisender, Twilio, SMS-агрегаторы) |

## 9. Развёртывание и эксплуатация

- **Локальная разработка**: Docker Compose с горячей перезагрузкой (Air для Go, Vite для React).
- **Production**: Docker-образы собираются в CI/CD, деплоятся на сервер (Kubernetes/Docker Swarm). Используется reverse proxy (nginx/traefik) с SSL.
- **Мониторинг**: Prometheus собирает метрики, Grafana визуализирует; настроены алерты на критичные события (падение сервисов, высокая нагрузка, ошибки интеграций).
- **Резервное копирование**: ежедневные бэкапы PostgreSQL с хранением на отдельном хранилище.
- **Обновления**: стратегия нулевого простоя (rolling update) для микросервисной архитектуры или перезапуск контейнеров с минимальным временем простоя.

## 10. Заключение

Система RMS предоставляет комплексный инструмент для управления розничным бизнесом, закрывая все ключевые потребности: от учёта товаров до сложных интеграций с государственными системами и маркетплейсами. Модульная архитектура, использование современных технологий и ориентация на российское законодательство делают её готовым решением для любой торговой организации.

Проект спроектирован с учётом масштабируемости: по мере роста бизнеса можно добавлять новые модули, увеличивать производительность за счёт горизонтального масштабирования и оптимизировать запросы. Интеграция с внешними сервисами позволяет легко расширять функциональность без переписывания ядра.
